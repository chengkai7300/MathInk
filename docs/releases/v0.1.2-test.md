# MathInk v0.1.2-test

修复「关闭主程序后模型仍占用显存」，并改成**托盘图标 + 后台服务**的启动/关闭方式。

## 根因

`llama-server` 是主程序通过 `subprocess` 启动的子进程，原先只在 FastAPI 的 lifespan
关闭钩子里停掉。直接关闭启动窗口、任务管理器结束进程或程序崩溃时，lifespan 不会执行，
`llama-server` 就变成孤儿进程，模型继续留在显存里（约 1.9 GB），直到手动结束。

## 修复

- **Windows Job Object（`KILL_ON_JOB_CLOSE`）**：llama-server 启动时被放进 job，
  主进程无论正常退出还是被强杀，句柄关闭时系统都会回收子进程
- **显式收尾**：退出时先 `server.should_exit` 优雅停服务，再停 llama-server，
  并校验 PID 确实是 `llama-server.exe`（避免 PID 复用误杀）
- **启动自清理**：每次启动先扫描命令行里含本项目模型路径的 `llama-server` 并结束
- **stop 兜底**：`stop.ps1` → `launcher.py --stop`，按 PID 树结束，再扫端口与残留进程

## 新的启动 / 关闭方式

```powershell
# 启动：后台运行，通知区域出现 MathInk 图标，命令立即返回
powershell -ExecutionPolicy Bypass -File .\start.ps1

# 前台调试
powershell -ExecutionPolicy Bypass -File .\start.ps1 -Console

# 关闭
#  托盘右键 → 退出 MathInk（彻底关闭）
#  或
powershell -ExecutionPolicy Bypass -File .\stop.ps1
```

托盘菜单：打开主机端、复制平板地址、状态、**释放显存**（下次识别重载）、打开日志、退出。

## 占用优化

| 项目 | 之前 | 现在 |
| --- | --- | --- |
| llama 上下文 | 4096 | **2048** |
| 并行槽位 | 4（自动） | **1** |
| 退出后显存 | 残留 ~1.9 GB | 回到桌面基线 |
| 启动方式 | 前台阻塞 | 后台 + 托盘 |

正常运行时 VLM 约占 1.9 GB 显存、1.6 GB 内存；只用 CoMER 时显存几乎为 0。

## 验证

- 终止主进程（模拟崩溃）后 4 秒内 `llama-server` 消失，显存 3960 → 2107 MiB
- 托盘退出路径：7.6 秒内完成退出，显存回到 2102 MiB，8848/8849 端口释放
- `stop.ps1`：端口释放，无残留 python/llama-server
- 托盘日志 `tray icon visible=True`
- 单元测试 6/6 通过

## 已知限制

- 托盘图标可能被 Windows 收进 `^` 展开区，可拖动固定到任务栏
- 释放显存后，下一次识别需要重新加载 VLM（约 2–10 秒）
- 目前仅提供 Windows 托盘实现
