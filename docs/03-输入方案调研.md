# 输入方案调研：除了鼠标，还能怎么"写"

> 2026-11-16 · 结论基于公开论文/基准与本地实测；价格为大致的国内电商区间。

---

## 0. 结论

1. **同样的人写同样的公式，输入设备对准确率的影响不亚于换模型。**
   按「精度潜力 + 书写自然度」排序：
   **电磁笔/数位板 ≈ 触控笔平板 > 纸笔拍照 > 鼠标 > 手指触屏**。
2. 当前桌面产品性价比最高的一步升级：**支持数位板/触控笔，并采集笔压**。
   硬件 300–800 元，代码改动小（Pointer Events 已经能拿到 `pressure`），
   还能为未来的在线笔迹模型积累数据。
3. 中期值得做：**拍照输入**（手机拍纸面笔记 → 透视矫正 → 现有 VLM）。
   它覆盖「已有纸面笔记数字化」，实测同类数据（HME100K）VLM 约 69.5%。
4. 鼠标不是错，但它是最难写好的输入方式：抖动、尺度不可控、无笔压。
   当前 VLM 在干净短公式上已到 **81.3%**（CROHME19 ≤5 token），
   继续堆模型的边际收益，低于换一支笔。

## 2. 证据：在线笔迹 > 离线图像

- **MathWriting（Google, 2024）** 同一测试集：

  | 方法 | 输入 | CER↓ | EM↑ |
  | --- | --- | --- | --- |
  | Google OCR | 离线图像 | 7.17 | 53 |
  | CTC Transformer（35M） | **在线笔迹** | **5.49** | **60** |
  | PaLI（700M） | 笔迹+图像 | 5.95 | 64 |
  | PaLIGemma（3B） | 笔迹+图像 | 5.97 | 69 |

  在线笔迹多了「时序/笔顺」信息，误差明显更低；多模态融合再高一点。

- **CROHME 2023** 同时设 online / offline / bi-modal 三个赛道，社区共识是在线赛道更容易。
- **HME100K（真实拍照）**：Uni-MuMER-3B **69.5%**，说明拍照可行，但比干净输入低约 10 个点。
- **本地实测（CROHME19，≤5 token）**：VLM 81.3%，同一批数据 CoMER 73.7%——
  模型差距之外，**输入干净度**是另一条主线。

## 3. 笔压/倾角：被忽略的信号

浏览器 Pointer Events 对笔提供：

| 属性 | 鼠标 | 笔 |
| --- | --- | --- |
| `pointerType` | `mouse` | `pen` |
| `pressure` | 固定 0.5（按下时） | 0–1，随力度变化 |
| `tiltX/tiltY` | 0 | 笔倾斜角 |
| `twist` | 0 | 笔旋转（部分设备） |

当前实现只取 `x/y`，笔压完全浪费。可做：

1. **变宽笔画**：`width = base * (0.4 + 1.2 * pressure)`，视觉更接近真实书写，也让 VLM 看到更清晰的笔迹。
2. **笔压作为在线模型特征**：未来训练 CTC/Transformer 时，`(x, y, pressure, dt)` 比纯图像更强。
3. **手掌防误触**：`pointerType === "touch"` 且已有笔迹时忽略；或设置「仅笔」模式。
4. **倾角**：可做笔锋/粗细方向，但对识别价值有限，优先级低。

实现代价：前端每点多存一个 `pressure`，后端渲染从「每笔一个宽度」改为「逐段宽度」。
建议先在前端做变宽显示、按平均宽度上传，后端保持兼容。

## 4. 更"聪明"的输入交互（不改硬件）

| 交互 | 价值 | 成本 | 建议 |
| --- | --- | --- | --- |
| **局部纠错**：点选渲染结果里的符号→候选替换 | 高：81% 正确的剩下 19% 里，多数只错一个符号 | 中 | P1 做 |
| **候选条**：同一图返回 2–3 个候选 | 中 | 小（VLM 采样多次/温度） | P1 |
| **结构命令**：选中 `a/b` → 一键变 `\frac{a}{b}` | 中 | 小 | P2 |
| **混合输入**：手写符号 + MathLive 面板 | 中：复杂结构用面板更快 | 中 | P2 |
| **语音 + 手写**："x 的平方加一" | 低：数学 ASR 错误率高 | 高 | 不做 |
| **分区书写**（基线/上下标区） | 低：限制自由，误触多 | 小 | 不做 |
| **自动分数线**（画横线即分式） | 中：符合直觉，但易误判 | 中 | 观察 |

## 6. 落地路线（按投入产出）

| 优先级 | 事项 | 工作量 | 验收 |
| --- | --- | --- | --- |
| P0 | 笔/触摸检测 + 笔压渲染 + 触屏适配 | 1–2 天 | 数位板上粗细随力度变化，识别不降 |
| P0 | 画布「建议书写区」引导（约 600×200） | 0.5 天 | 用户少写超界 |
| P1 | 局部纠错 + 候选 | 2–3 天 | 错一个符号时改一处即可 |
| P1 | 拍照输入（上传/摄像头 → 透视矫正 → VLM） | 3–5 天 | 纸面照片可用率 ≥70% |
| P2 | 在线笔迹模型（strokes+pressure 训练） | 1–2 周 | 短公式 ≥85%，需数据 |
| P2 | 数位板"全屏映射"模式 | 1 天 | 小字也能写 |

## 7. 风险

- **笔压跨设备差异**：不同笔的 0–1 曲线不同，需归一化（按本次书写的中位数校准）。
- **触屏手指误触**：手掌/手指会画出杂线；需要「仅笔」开关或 `pointerType` 过滤。
- **拍照质量**：光照、透视、纸张纹理都会掉点；需要数据增强与矫正。
- **在线模型数据**：MathWriting 是 CC BY-NC-SA，只能非商用；商用需自采笔迹。
- **硬件依赖**：数位板需要驱动；网页端无法保证所有设备都上报 pressure（要 fallback 到 0.5）。

---

## 8. 结论（一句话）

**先让用户能"用笔写"（数位板/触控笔 + 笔压），再考虑"拍着写"（拍照），最后才是"用笔迹时序训练模型"。**
鼠标方案保留为兜底，不作为主推体验。
